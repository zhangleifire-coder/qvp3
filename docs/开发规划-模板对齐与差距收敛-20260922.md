## 1. 现有程序工作结构（实测口径）

### 1.1 实际运行态（.env 实测）

```
AGENT_PIPELINE_ENABLED=true + AGENT_PIPELINE_VARIANT=staged
+ IMAGE_COMPOSE_MODE=true（config.py:68 默认 true）+ MOCK_IMAGE_GEN=false
```

即**生产实际走：staged 路径 + 混合合成（compose v6）**。代码默认值仍是直连
（config.py:114 `agent_pipeline_enabled=False`），与 .env 不一致——默认值已落后于事实标准。

### 1.2 端到端链路（staged 视角）

```
创建任务(CSV/Query/手工) → scheduler → orchestrator 选路径
→ ref_seed(自动搜图) → text_check 关卡（LLM 起草正文+分页草稿 pages_draft + image_prompt_draft，
  人工确认 awaiting_text）
→ [compare/single: ref_collect 搜图≥12 + OCR 初筛 + 人工关]
→ staged 4 节点：evidence(取证+选风格) → draft(写稿) → pages(分页 6 页) → assets(配图)
→ rule_check → cross_check → risk_classify → review_queue(A/B/C 人工审)
→ batch_signoff → publish_snapshot(交付契约) → approve → export ZIP
```

### 1.3 生图双链（assets 节点内分流）

| | B 整图直出（回退链） | C 混合合成（现役主链，agent_stages.py:664 `_compose_mode_assets`） |
|---|---|---|
| 文字 | 生图模型渲染，靠 prompt 铁律约束 | **PIL + 微软雅黑程序渲染**（compose_page，伪汉字不可能） |
| 画面 | 整图一次生成 | gen_textfree_illustration 无文字画面（no_text 兜底 + VL 文字检查，不过重生 1 次） |
| 版式 | layouts_cn/en.txt 6 角色轮换 | v6 版式语言：overlay/top/bottom/left/right 确定性轮换（task_id+页码种子）+ 宫格 1-6 张 |
| 质检 | comprehensive_page_check（VL 三链：文字逐字/主体/协调） | 同左，只查程序文字；不合格换构图角重合成 1 次 → 打标人工 |
| 异常 | — | 整段异常返回 None → **回退 B 链**（agent_stages.py:816-819） |

提示词组装单点：直出链 `prompt_versions.get_image_prompt`（skills 片段 + `_IMAGE_TEXT_HARD_RULE`
统一收口 image_gen.py:96-98）；混合链 `visual_brief` 抽离层 + `_clean_ill_prompt` 清洗。

## 2. 对照模板的问题清单（G1~G8，按严重度排序）

### G1 · 跨页双维度去重无程序保障（铁律4）— 最高优先

- **信息去重**：分页/写稿提示词无「信息叙事链」契约（skills/page-split、text-draft、draft-write
  中无任何重复相关条款，grep 证实）；页文案质检只有字数均衡（contract.txt PAGE_MIN/MAX/DIFF）。
- **视觉去重**：仅 shared_style 一句「图片元素不与前页重复」+ 生图后 hash 去重（同图拦截，
  不拦相似）+ 版式确定性轮换；质检链完全单页视角，无跨页检查。
- 模板要求：每页单一信息任务 + 前页知识点/场景/道具/隐喻后页不得复用——生成端和质检端都缺位。

### G2 · 禁带文字物件是弱措辞（铁律7）

shared_style：「**尽量**不出现带文字的物体」——"尽量"等于没禁。`_IMAGE_TEXT_HARD_RULE` 通篇
管"给定文案怎么渲染"，不管"物件自带文字"。混合链靠 no_text 兜底 + VL 查（宽松版），直出链
（仍是回退链和 mock 联调链）裸奔。模板要求明确黑名单：包装标签/瓶罐/说明书/标牌/屏幕文字/店招。

### G3 · 场景A 结构化文案缺失（模板 §2）

- 分页产出是 6 段纯文本（80-130 字/页），无 `{title, subtitle, points, subject, info_task}`
  结构；compose 链用 `split_title_points`（poster_compose.py:822）**机械拆分**——首句截 18 字
  当标题、子句打包 ≤18 字当要点，断点好坏全凭运气。
- `page-subject` skill（每页画面主体提取）已孤儿化：生产链不调用，仅 regen 快照
  （regen.py:260）与 MCP 调试工具残留。主体锚定句替换只活在直出链
  （prompt_versions._apply_page_subject）。
- 模板的思路是"文字阶段就把每页画什么定死"——现在 subject 概念散落三处三种格式
  （page_subjects 旧 list / 新 visual_writer dict / image_prompt_draft）。

### G4 · 页数硬编码 6

nodes.py:468「不足 6 页返回 None」、507「重新输出全部 6 页」、publish_snapshot 契约、
layouts 6 角色轮换、前端导出 P1-P6。模板与 9 月实验口径是 5~6 页可配。
改页数现在是全链手术。

### G5 · 铁律措辞四处副本漂移

`shared_style.txt`（中文底座）/ `constraints_en.txt`（英文）/ `_IMAGE_TEXT_HARD_RULE`
（重生通道收口）/ `posters_tmp.py`（自带一套渲染+文案规则）各维护一份铁律，模板 MD 是第五份。
例：字号 7% 在 hard rule 有、shared_style 无；日文新字体黑名单在 shared_style 有、hard rule 无。
模板附录四已声明"以模板为单一事实来源回写 skills"——尚未执行。

### G6 · 质检缺口对照验收手册

- **无水印/二维码/引流视觉检测**：comprehensive_page_check 只查 text/subject/harmony 三项
  （visual_check.py:205-214）；quality/rules.py 与 risk/classifier.py 无水印/二维码条款（grep 证实）。
  手册 7.5/7.6 是 0 分红线。
- **无跨页维度**：手册「图集一致性（主风格≥80%）」「图集多样性」两个评分维度无任何程序检查。
- VL 失败=放行（返回 None 按放行，人工兜底）——可接受但要知道。

### G7 · 冗余资产待退役（三路径决策到期）

- 三条流水线路径并存：直连 13 节点 / monolith 大节点 / staged 4 节点；`.env` 已选 staged。
  monolith 自 staged 上线后无新演进（compose 模式只挂在 staged）。
- `posters_tmp.py`（494 行临时验证 API，自带与 poster_compose 平行的渲染代码）——compose v6
  已在主链验证，按文件头注释"验证完可整文件删除"，到期未删。
- `ai_review.py` 孤儿模块（无生产调用方，职责已并入 _image_quality_chain）。
- `visual_writer` 英文扩写链路只有直连路径调用（nodes.py:727-733）——生产走 staged 后整条休眠。

### G8 · compose 成本记账失真

`agent_stages.py:805-807`：`cost_cny = unit × len(localized)`（按页数=6 计）。
但宫格模式每页生 1-6 张插图 + 质检不合格重合成整页插图——实际生图调用数 =
Σ(n_img) + 重生张数。成本被系统性低估（cost_tracker/账本口径跟着失真）。

## 3. 开发规划

总原则：**先把"说一套"收敛成"一套"（P0/P1，零生图成本），再做结构性升级（P2），最后补质检
（P3）**。P1 与 P2 可部分并行；P3 依赖 P2 的结构化文案。全程 MOCK_IMAGE_GEN=true 联调，
真实生图只发生在基准批（≤2 轮，预算 ≤¥130）。

### P0 · 收口与退役决策（0.5-1 天，纯代码/配置）

对应记忆中"staged 验证结论出来后须做退役决策"——现在结论已出（.env 事实标准）：

| 动作 | 内容 | 风险控制 |
|---|---|---|
| P0.1 退役 monolith | `agent_pipeline_variant` 文档标 deprecated；测试保留到 v0.1.4 发版后删除代码 | config 默认值改为 staged+compose 与 .env 对齐（默认=事实标准，新人零配置跑对路径） |
| P0.2 删 posters_tmp.py | 连同 main.py:68 挂载、static 引用一并清 | 删前跑 pytest 全量 |
| P0.3 归档 ai_review.py | 移入 `src/quality/_archive/` 或直接删（git 有历史） | — |
| P0.4 修 G8 成本记账 | compose 记账改为实际张数（Σn_img + 重生）；补一条单测 | 纯计算逻辑，零生图 |
| P0.5 visual_writer 处置 | 二选一：①直连链专用保留（回退链质量）；②标记休眠。建议①，零改动 | — |

### P1 · 提示词 SSOT 回写 + 铁律硬化（1 天，prompt 为主）

1. **G5 回写**：以模板铁律 1-8 为唯一基准，重写 `shared_style.txt` /
   `constraints_en.txt` / `_IMAGE_TEXT_HARD_RULE`（合并去重：字号 7%、日文新字体黑名单、
   优先级总纲段三处互补条款合一）。守卫：`verify_skill_equivalence.py --baseline` 存档
   → 改后跑 `test_page_balance` + `test_absorb_8002` + `test_agent_pipeline` 全绿（§5.3 纪律）。
2. **G2 硬化**：shared_style「尽量不出现带文字的物体」→ 模板铁律 7 黑名单句式；hard rule
   增补同一句（重生通道同享）。
3. **G1 生成端（信息去重）**：page-split / text-draft 契约加模板场景 A 规则 1
   （信息叙事链：每页单一信息任务，后页不重复前页知识点）；同步 `_AGENT_INSTRUCTIONS`
   分页段（agent_shared.py）。
4. **G1 机检端（低成本兜底）**：rule_check 增加页间相似度机检——页文案分词后两两 Jaccard，
   超阈值（建议 0.45 起调）打 `page_overlap` 标签进 ReviewSession（**告警不硬拦**，人工定夺）。
5. **G6 质检扩维（零额外调用）**：`_COMPREHENSIVE_PROMPT` 加第 4 项 `watermark_ok`
   （水印/二维码/账号引流字样）——同一次 VL 顺带查手册红线。

验收：pytest 全绿（mock）+ 8 题小基准真实批（~¥20）人工快审无回归。

### P2 · 场景A 结构化文案 + 页数可配（2-3 天，核心开发）

1. **page-split 升级为结构化输出**（模板场景 A schema）：
   每页 `{"title": ≤18字, "subtitle": 6-28字, "points": [≤4条×≤18字], "subject": ≤20字可画名词短语,
   "info_task": 一句话信息任务}`；解析容错沿用围栏剥离；契约测试同步
   （字数均衡约束从"页全文 80-130 字"改为"title+subtitle+points 合计"同区间，兼容旧值）。
2. **compose 链直连消费结构化文案**：`split_title_points` 退为兼容层（旧任务/直连回退链）；
   `compose_page` 接收结构化对象；`subject` 字段进 `sub_prompts` 子提示
   （景别 × subject 组合，替代纯景别盲选）——主体锚定从"prompt 术语"升级为"数据字段"。
3. **text_check 关卡同步**：pages_draft / image_prompt_draft 草稿格式跟随结构化
   （前端 views 的编辑器跟进，人工可改的字段化展示）。
4. **页数可配**（G4）：`PAGE_COUNT` 配置（5|6），layouts 轮换映射按模板 §3.2
   （5 页去清单页）；`publish_snapshot` 契约、导出 P*.png、前端分页视图全部取配置值；
   contract.txt 的均衡约束按页数缩放。

风险与对策：结构化解析失败率上升 → 保留纯文本回退解析（老 prompt 路径）+
重试一次；前端改动 → 手工测 5 页/6 页各一条全链。

### P3 · 跨页质检 + 验收对齐（1-2 天）

1. **批量 VL 审核节点**（G1 质检端 + G6 跨页维度）：assets 完成后新增一次 VL 调用——
   6 页缩略图拼版一次送检，查：跨页信息重复 / 跨页视觉重复（场景构图道具）/
   风格一致性 / 深底页数 ≤1。输出 flags 进 RejectMark（告警为主，连续两页高相似才硬拦重生）。
   成本：每任务 +1 次 VL（约 ¥0.05-0.1），覆盖手册「图集一致性/多样性」两个评分维度。
2. **标题-Query 相关性预检**：text_check 关卡加轻量 LLM 检查（标题是否精准回应 query，
   手册 6.1 的 3/2/1 分口径简化为 pass/warn），warn 进人工关卡展示项。

### P4 · 基准、文档与发版（0.5 天）

1. 基准集一轮全量（20 题，~¥50-65）：对比指标在既有基准口径上加两个——
   跨页重复率（P3 产出）、伪汉字率（应≈0，compose 主链）。通过率 ≥ 基线才发版。
2. 交接文档更新：§5.3 注入点清单从三路径口径改为**双路径口径（staged 主链 + 直连回退）**；
   模板附录四映射表同步实际实现；README 版本号从 v0.1.2 修正。
3. 发版门禁（铁律）：本地 8005 全链验证 → 用户确认 → 服务器 8005 镜像本地化流程。

### 非目标（本轮不做）

- 不动生图通道网关/配额/三道人工关卡/MOCK 开关；
- 不动风格库结构（WS1/WS3 已收敛，39 条在库）；
- 不引入新模型（Sunburst 已用于重生通道）；
- 不做站内重复检测（手册「内容重复性」需要对站内库，属另一个系统边界）。

### 成本预算汇总

| 项 | 生图成本 |
|---|---|
| P0/P1 开发联调 | 0（MOCK） |
| P1 验收小基准 8 题 | ~¥20 |
| P2 联调 | 0（MOCK）+ 手工测 2 题 ~¥5 |
| P3/P4 基准 1-2 轮 | ¥50-130 |
| **合计** | **≤¥155**（降本选项：P1 验收并入 P4 基准轮，减 ¥20） |

### 里程碑与依赖

```
P0(收口) ──→ P1(SSOT回写+硬化) ──→ P2(结构化文案+页数) ──→ P3(跨页质检) ──→ P4(基准+发版)
                └── P1.3/P1.4 与 P2.1 可并行（同改分页链，注意合并顺序）
```

每 Phase 一提交（git 分支 release/v0.1.3 续用或切 release/v0.1.4，以发版时点定）。
