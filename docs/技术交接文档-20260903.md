## 1. 平台是做什么的

面向内容运营的「小红书风格图文」批量生产平台：导入选题 Query → AI 取证/写正文/
分 6 页文案/生成 6 张竖版卡片图（3:4）→ 规则机+视觉审核 → 人工核查/审图 → 签发导出。
三种生产模式：`general`（通用科普）、`single`（单一产品实测，图生图保外观）、
`compare`（两主体对比，双实景参考图生图）。

设计原则：**AI 只做创作段，业务调度、校验、审核、记账全部在后端确定性代码里**；
每个 LLM/生图调用可 mock、可重试、有幂等键、有成本记账。

## 2. 总体架构

```
浏览器（Vue3 CDN 版 SPA，hash 路由，无构建步骤）
   │  HTTP + SSE
   ▼
FastAPI 后端（uvicorn，单进程 asyncio）         Docker Compose（每套栈独立）
   ├─ scheduler：进程内 asyncio 队列 + 自适应并发限流        ┌─────────────────┐
   ├─ 双路径流水线 orchestrator                              │ qvp2-app  :8003 │
   │    ├─ Agent 路径（生产默认，AGENT_PIPELINE_ENABLED=true） │ qvp2-postgres   │
   │    │     └→ Nanobot 网关 :8900（OpenAI 兼容 API）        │ qvp2-openserp   │
   │    │           └→ 创作大节点 LLM（deepseek 主/kimi 备）   └─────────────────┘
   │    │                 └→ MCP 工具（stdio 子进程 qvp_mcp）      Nanobot 在应用容器内
   │    └─ 直连 13 节点路径（兜底开关，秒切回）                     拉起，仅回环可达
   ├─ 视觉审核 visual_check（dashscope qwen-vl-max）
   ├─ rule_check / cross_check / risk_classify（纯代码，无 LLM）
   └─ PostgreSQL 16（SQLAlchemy async + asyncpg）＋ Redis（限流/心跳）
```

一次 Agent 路径生产的数据流：
导入 → 文字核查关卡（人工放行）→ 实景搜图关卡（人工筛选，compare/single 才有）→
`agent_production` 一次调用 Nanobot 创作 Agent（内部用 MCP 工具：豆包搜索取证 →
生图 gpt-image-2 → 逐页 OCR 自检）→ 后端收契约 JSON 做确定性收尾（图片本地化/去重/
尺寸校验/落库 → 规则机 → 交叉核验 → 风险分级 → 人工审图 → 会签 → 快照）。

## 5. 核心机制详解

### 5.1 双路径流水线（最重要的设计）

`src/pipeline/orchestrator.py`：
- `NODES`（直连 13 节点，定义在 nodes.py:31）：task_import → entity_bind →
  evidence_build → draft_gen → rule_check → page_split → asset_gen → ocr_read →
  cross_check → risk_classify → review_queue → batch_signoff → publish_snapshot
- `NODES_AGENT`（Agent 路径，**生产默认**）：创作段 6 节点（entity_bind/evidence_build/
  draft_gen/page_split/asset_gen/ocr_read）收敛为 1 个 `agent_production`，并新增
  text_check / ref_collect 两个人工关卡：task_import → text_check → ref_collect →
  agent_production → rule_check → cross_check → risk_classify → review_queue →
  batch_signoff → publish_snapshot
- 开关 `AGENT_PIPELINE_ENABLED`（.env），false 秒切回直连路径兜底。
- 两路径**同源提示词**：都从 `get_effective_prompt(kind, mode, owner_id)` 取词
  （解析顺序：用户自定义 → admin 系统覆盖 → 代码默认）。
  ⚠️ 历史教训：同一要求必须同时注入所有路径（详见 5.3）。

### 5.2 三道人工关卡

| 关卡 | 状态 | 放行 API |
|---|---|---|
| 文字核查（正文/页文案草稿人工核改） | `awaiting_text` | `POST /api/tasks/{id}/text/confirm`（另有 redraft/reject） |
| 实景参考图确认（compare/single） | `awaiting_refs` | `POST /api/tasks/{id}/refs/confirm`（keep_ids） |
| 审图（单角色通过即生效） | `review` | `POST /api/review/action`（approve/reject+定点标记） |

关卡挂起后任务回队或等待，确认后**幂等续跑**（已完成节点跳过）。
人工驳回带定点标记（page/image+理由）→ `rejected` → retry 触发 `partial_regen`
（只重生成标记项；意见注入提示词，`src/services/regen.py`）。

### 5.3 提示词库体系（改提示词必读）

全部在 `src/gateway/prompt_versions.py`，纯 Python 字符串常量 + 演进注释。
关键点：
- 正文写作的「人设与真人感+信息密度」共享段 `_DRAFT_SHARED` 必须**三条路径都注入**：
  ①直连 draft_gen（nodes.py）②Agent 路径（agent_production.py 取词后 append）
  ③text_check 起草（用户在核查关卡看到的草稿）。
  注入条件：`template == default_prompt(...)` 时才追加——用户自定义模板代表显式意图，
  不覆盖（防负优化）。
- 图上文案字数契约（2026-09 起）：每页 **80-130 字**、六页差≤40、每页 1-2 个具体
  信息点。该契约同样存在于：PAGES_PROMPT、Agent 契约 `_AGENT_INSTRUCTIONS`、
  text_check 两条起草提示词、生图中/英底座、nodes.py `_balance_issue` 硬校验
  （不达标自动带意见重试一次）。**改字数口径必须 7 处同步**，并更新
  `tests/unit/test_page_balance.py` 的守卫断言。
- 测试里有「守卫断言」锁定关键提示词片段（如 test_absorb_8002 锁「胶囊」
  「CAPSULE」、test_page_balance 锁字数）——改提示词先跑相关测试。

### 5.4 生图与视觉闭环

- 生图走 MCP `image_gen` → `src/gateway/image_gen.py`：`IMAGE_GEN_CHANNELS`
  通道轮询（fusion,linkai,moacode），`IMAGE_GEN_PARALLEL=6` 并发，size 1152x1536
  （3:4），quality=high；MOCK_IMAGE_GEN=true 时返回占位图（联调用，不花钱）。
- compare/single 模式：确认后的实景参考图作为图生图 references 传入，
  **6 页实景用法必须错开**（按页轮播分配，铁律，e6c550b）。
- 落库后：本地化/去重/hash/尺寸校验 → OCR 逐页比对（错字/漏字自动重生成，
  garble_regen loop）→ qwen-vl-max 视觉审核（图文一致/主体匹配 `subject_mismatch`）。

### 5.5 实时流与记账

- `src/stream/bus.py` 进程内事件总线 → `/api/stream/events`（SSE）：节点开始/完成/
  失败（含 traceback）、Agent 流式增量、生图进度。前端监控页实时渲染。
- 成本：`tool_ledger` + `cost_tracker`，节点事件记 `cost_estimate_cny`，
  `/api/admin/costs` 汇总。Agent 工具成本经 HTTP 回调合并进节点。

Windows（Git Bash）实测步骤：

```bash
cd code

# 1) 起本地 PG(5433)+Redis（docker run 或 compose 里的依赖服务）
# 2) cp .env.example .env 填好密钥；本地库连接串用 5433

  .venv/Scripts/python -m uvicorn src.api.main:app --port 8003

  .venv/Scripts/python -m pytest tests/ -q
```

日常联调建议 `MOCK_IMAGE_GEN=true`（生图免费秒回）。真实出图约 1-2 分钟/张，
一条任务全链 10-25 分钟。

**改动后必须重启进程**：后端（uvicorn）读代码在启动时；MCP 子进程继承 Nanobot
的环境与配置快照——改 `.env` 后后端和 Nanobot **都要重启**，否则 MCP 还用旧值
（实际踩过：MOCK 开关改了没生效，因为只重启了后端）。

## 12. 数据模型速览（关键表）

- `tasks`：状态机 draft/processing/awaiting_text/awaiting_refs/review/rejected/
  approved/failed/cancelled；`text_review`（起草 JSON）、`text_override`（人工核定版）、
  `gen_style`/`gen_category`（风格自适应回填）。
- `drafts`（正文多版本）、`page_copies`（6 页图上文案，body 列）、
  `assets`（source_type: ai_generated/official；selection_status: candidate/confirmed/
  rejected；subject_mismatch）、`ocr_results`（confidence）、
  `claims`/`evidences`（取证）、`node_events`（幂等+记账+error_class）、
  `review_sessions`/`review_actions`/`approvals`/`reject_marks`（审核与定点驳回）、
  `style_keywords`（两级风格库，owner_id NULL=公共）、`prompt_library`（提示词库覆盖）、
  `activity_logs`、`issue`、`publish_snapshots`。
- ⚠️ 列名易错点（实测踩过）：风格描述在 `style_keywords.description`；
  资产类型是 `source_type` 不是 asset_type；页文案列是 `body` 不是 page_text；
  activity_logs 的列是 `action`/`detail`，tasks 没有 current_node 列（current_node 是
  API 从 node_events 推导的）。

## 13. 前端（无构建 SPA）

- `static/index.html` 引 Vue3/vue-router 的 vendor 文件 + `api.js` +
  `components/{Layout,StepsBar,Lightbox}.js` + `views/{Login,Dashboard,Import,Tasks,
  TextCheck,RefsBoard,Review,Monitor,Admin,Settings,Users,Sample}.js`。
- hash 路由：`/#/tasks` 这种 `#` 后内容不会发到服务器；若浏览器把 `#` 编码成 `%23`
  会得到后端 404（用户报过「打不开」，实为链接里的 %23）。
- 改前端直接改 JS 文件，刷新即生效；版本戳用 `?v=YYYYMMDDx` 控制缓存。
- 实时数据走 SSE `/api/stream/events`（监控页事件流/节点进度）。

## 14. 已知坑与经验（血泪史精选）

1. **Windows 本地**：必须用 `.venv/Scripts/python.exe`（系统 python 没装依赖）；
   Git Bash 调 curl 上传文件用相对路径（`/tmp` 路径转换会失败）；中文 query 参数要
   URL 编码。仓库部分文件 CRLF，git 会警告，无碍。
2. **MCP 环境缓存**：`qvp_mcp` 是 Nanobot 的 stdio 子进程，读 `.env` 发生在
   Nanobot 启动拉起子进程那一刻——改配置后「重启后端」不够，要重启 Nanobot。
3. **提示词多路径**：任何写作类要求都要检查 5.3 列出的全部注入点，否则只改一处
   不生效（生产走 Agent 路径）。
4. **排障顺序**：`docker logs qvp2-app`（或本地 uvicorn 输出）→ SSE
   `/api/stream/state`（含 error/debug/trace，比库里 error_class 详细）→
   Nanobot 会话日志 `~/.nanobot/workspace/sessions/*.jsonl`（Agent 原始对话与
   工具返回，余额不足这类真因都在这）。
5. **图上文案字数**：模型偶尔越界 ±5 字，硬校验会自动重试一次，仍越界保留较轻一版
   交人工审图兜底——不要为此加死循环。
6. **生图成本**：一条任务 6-8 张上限（配额硬限），余额/限流错误会以任务失败收场，
   报错现在会带 Agent 备注（1eb6c0b）。
