## 3. 推理挤占输出预算风险（32768 残留风险专项）

按主模型分组统计每轮 outputTokens / reasoningTokens 最大值：

| 主模型 | 会话数 | reasoning 挤占实况 | 判定 |
|---|---|---|---|
| deepseek-v4-pro（旧主） | 14 | 多轮 95-99%（最重 20729 输出中 19381 推理，余量 ~7%；极值 14898/14705 仅余 1.3%） | **高风险**，32768 救急但不根治 |
| **deepseek-v4-flash（现主）** | 2 | 推理占比极小（最大 206/351）；实验轮 completion 3482/5079 无挤占迹象 | **风险基本消除** |
| kimi-k3（备1） | 2 | reasoningTokens = 0 | 无风险 |

**调优试验结论（2026-09-14 实测）**：
- `DSH_REASONING_EFFORT=medium` 被全部三级模型拒绝（flash / kimi-k3 / Kimi Code k3
  均报 "does not support reasoning effort"）——「调低推理档位」这条路**不存在**；
- flash 在高产出任务上两轮契约达标（80-130 字/页全过），时延 20-24s/轮；
- 结论：维持「不设 effort（模型默认）+ flash 主 + 32768 上限」现状；
  **若未来回切 pro 主模型，必须把 max_tokens 提到 49152+ 或重跑本专项验证**。

## 7. WS4 真实批成本发现（重要）

真实批 10 题全部到 review，但**实际出图 231 张 ≈ ¥46，为批准预算（¥25-33）的
1.5-1.8 倍**，原因有二：

1. **9-11 的 100% OCR 逐字质检标准触发大量 garble_regen**：单任务出图 12-46 张
   （极端：戴森 compare 46 张、德龙 compare 39 张），平均 23 张/任务，而预算假设
   6-8 张/任务。
2. **单任务 8 张配额（mcp_max_images_per_task）在 Agent 路径下未生效**：
   `task_quotas.reset` 在 agent_production 节点每次重跑时全额重置计数，
   且实际观测超过 8 张后仍在生成（41-46 张），配额防线存在漏洞，需专查
   （疑似重试重置 + acquire 拒绝后 agent 换页继续的两条路径）。

**建议后续动作**：真实批拼版人工快审（10 分钟口径）→ 若风格质量达标，
把「配额失效 + 重试重置」立为 P1 修复项（防生产烧钱）；评估 garble_regen
是否带重试上限（当前文档口径为"自动重试一次"，观测远超一次）。

**初步结论：本地灰度数据已满足切换评估的前置条件，建议在 WS4 真实批结果出来后
正式做切换评估；服务器侧取数是唯一缺口。**
