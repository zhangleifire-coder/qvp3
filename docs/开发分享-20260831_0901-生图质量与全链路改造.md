## 一、生图质量链路（核心：让 API 出图逼近 ChatGPT 网页效果）

### 1. 风格自适应选向（8-31）
- **是什么**：任务生图前按 query 题材从风格库自动选一个视觉方向，一篇 6 页锁定同一风格（同主色调/同字体/同装饰，仅布局轮换）。
- **怎么选**：query 与风格关键词命中计分 → **加权随机**（强相关更可能、弱相关也有机会 → 同题材多次出图风格会变化，避免千篇一律）；全不命中 → 全库随机。
- **防漂移**：选定的风格名+描述词**快照落库**（`gen_image_style` / `gen_image_style_desc`）——风格库日后修改/删除不影响已定稿任务的重生成一致性。
- **风格库从哪来**：对用户提供的 **836 张人工满意样例**（ChatGPT 网页产出）分三轮抽样 50 张逐张分析，提炼出 10 条启用风格（莫兰迪暖调写实 / 深色科技 / 手写科普 / 杂志风产品对比 / 航拍旅行……），每条含「色调+字体+质感+装饰」完整配方。

### 2. 场景化扩写链路：复刻网页端 Agent（9-1）
- **背景**：网页生图质量高的核心是对话模型先把口语 prompt 扩写成丰富视觉描述，API 是裸调。我们把这一层补上了。
- **链路**：6 页中文文案 + 风格库描述 + 近期审图反馈 → **nanobot 固定记忆会话**（`qvp-visual-memory-v1`）扩写成**英文视觉描述**（每页 40-80 词：主体+环境道具+光位视角+色彩情绪）+ 风格英文版 → 注入 gpt-image-2。
- **记忆持续迭代**：审图驳回意见自动回写同一会话（配色反馈优先学习）——越用越贴合团队口味；nanobot 超时/不可达自动回退 DeepSeek/Kimi。
- **双模式容错**：扩写成功走英文骨架（视觉指令模型理解更准，中文文案逐字保留渲染），失败回退原中文骨架，绝不卡出图。

### 3. 画质对齐网页端（9-1）
- `quality=high` **显式传入**四个生图通道（API 默认 auto≠high，不传会跑 medium/low 细节锐度直接下降）
- 通用画质词进底座（锐利/细节丰富/纹理细腻/无畸形无伪影）

### 4. 配色决策放开 + 颜色训练闭环（9-1）
- 标题强调色不再固定「暖橘」——按底色与主题自选协调点缀色（陶土/墨绿/雾蓝/芥末金…）
- 底色按题材分化：注入低饱和参考调色板（sage green/misty blue/cream pink/champagne 等），实测同引擎三主题三种配色方案
- **训练方式**：审图驳回时写颜色意见（如「太黄，要偏灰绿」）→ 自动回写记忆会话 → 下次扩写生效

### 5. 排版铁律（吸收 8002 人工样例规律，英中双底座）
- **双色标题**：主体字深色 + 1-2 关键词强调色，「VS」也用强调色
- **深字浅底**：文字直接排在浅色留白区，禁深色衬底框；**彩色胶囊标签**（主题色底白字）是推荐标注形式
- **简体字形铁律**：禁日文新字体（実対変単図芸）/繁体/异体字；图上文字当「逐字抄写的排版内容」而非装饰纹理
- 图上文字每页 30-100 字且六页均衡（任意两页相差 ≤25 字，代码级校验+自动重试）
- 边框底色禁纯白纯黑

### 6. 图文一致性视觉审核（9-1，治「文案说猫图里画狗」）
```
每页配图生成后 → VL 模型（qwen-vl）看图：图中主体与该页文案主题是否相关？
  相关 → 通过（对比文画单主体也算相关）
  无关 → 自动带主体强调重画一次 → 仍不符 → 标记「主体待审」红标签，人工把关
  VL 不可用 → 跳过，人工关卡兜底（绝不阻塞出图）
```

### 7. 3:4 尺寸铁律（贯穿全部生图环节）
- API 请求显式 `size=1152x1536`；生成后校验收紧到 3% 容差
- 偏离 → 自动重生成 → 仍偏 → **中心裁剪归一到严格 3:4**（+留痕）——不再允许比例偏差图直接交付

### 8. 性能与成本
- **fusionai 6 并发通道真正生效**：原 `IMAGE_GEN_PARALLEL` 配置从未被代码使用（实际串行+通道轮询）——改为 gather 并行批，6 张从 3-4 分钟压缩到约 30-40 秒
- 生图单价口径 0.2 → **0.4 元/张**（一处配置全局生效）

## 三、实时监控（全链路流式）

### 根因修复：监控页「数据流失效」的真相
SSE 事件里的 `task_id` 是 UUID 对象，`json.dumps` 抛 `TypeError` **当场杀死整条 SSE 连接**——每条带 task_id 的事件都在杀流，浏览器 EventSource 重连后又被下一条事件杀死。打点实测抓到死亡现场后修复（序列化 `default=str` 双保险）。顺带把静态缓存中间件改为纯 ASGI 实现（BaseHTTPMiddleware 对流式响应有首帧冻结缺陷）。

### 现在的监控页
- **直连 LLM 真流式**：正文/分页/文字自查的生成过程逐 token 上屏（实测 DeepSeek 416 字 → 293 次回调跨 6.5 秒）
- **每个节点按功能名显示正在做什么**：「文字自查·驳回定向修改（LLM 流式生成）」「生成配图 3/6」「P4 与已有图重复，已换构图重生成」「OCR 图文自检 P2（2/6）」
- 创作 Agent 数据流面板：流式增量（含输出尾部预览）+ 工具调用细节
