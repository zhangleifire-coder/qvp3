# 性能体检报告 2026-09-10（只读，未改任何代码）

范围：FastAPI 后端（src/）、SSE/调度（src/stream/）、流水线（src/pipeline/）、网关（src/gateway/）、无构建前端（static/）、测试与启动。结论按 ROI 排序。

### P0-1 任务列表 N+1（最热接口）
- 证据：`src/api/tasks.py:275-281`（每个 task 2 条 SQL）；`static/views/Tasks.js:119` limit=100、`:535` 5s 自动刷新；`backend.log` 实测高频 `GET /api/tasks?limit=100`。
- 影响：每个开着的 Tasks 页 → 每 5s ~202 条 SQL；多用户叠加是 DB 第一热点。
- 修法：`SELECT DISTINCT ON (task_id) task_id, node_name FROM node_events ... ORDER BY task_id, enqueued_at DESC` + `RiskClassification.task_id.in_(ids)`，内存 join。
- 收益：该接口 SQL 数 202→3；风险低；工作量 **S**。

### P0-2 litellm 远程价表阻塞主后端启动/pytest
- 证据：`backend.log:9` 警告；实测 `import litellm` 12.7s，设 `LITELLM_LOCAL_MODEL_COST_MAP=true` 后 7.1s（本机网络到 raw.githubusercontent.com 超时）。MCP 侧已设（`dsh_serve/start-local.sh:15`），主后端未设。
- 修法：start.bat / start.sh / docker-entrypoint.sh / compose 的 backend 服务 env 加 `LITELLM_LOCAL_MODEL_COST_MAP=true`。
- 收益：后端重启、pytest 会话各省 ~6-13s；风险极低（价表本就走本地兜底+DB 费率表 020）；工作量 **S**。

### P0-3 监控快照无界增长 + 全量重拉
- 证据：`src/stream/progress.py:113`（`self.tasks` 只增不清）、`:315-320` 全量 snapshot（含 debug tracebacks、node_streams、stream tail）；`static/views/Monitor.js:339` 每个 task_/node_ 事件后 `loadSnapshot()`；SSE 首帧也推全量（`src/api/stream.py:42`）。
- 影响：内存缓慢泄漏；进程跑得越久 `/api/stream/state` 越大（数百任务后可达 MB 级 × 每节点事件 × 每个监控客户端）。
- 修法：终态任务只保留最近 N 条（或 done/failed 超时淘汰）；前端节点事件改增量更新、快照拉取节流 ≥2s。
- 收益：内存封顶 + 热点接口 payload 降数量级；风险中（影响 debug 回看，需保留近 N 条）；工作量 **M**。

### P0-4 ref_collect 串行下载+OCR
- 证据：`src/pipeline/ref_collect.py:198-232` 逐候选 `await fetch_image_bytes` → `_persist_image` → `await ocr_image`（OCR 单次秒级）。
- 影响：compare/single 任务该节点 1-3 分钟串行等待；并发任务越多排队越久。
- 修法：gather + Semaphore(4~6)（注意 OCR 上游限流，信号量保护）；保持剔除语义不变。
- 收益：节点耗时降 3-5×；风险中（OCR 并发触发限流→用 limiter 信号量兜底）；工作量 **M**。

### P0-5 detail/review 接口 per-claim / per-role 循环
- 证据：`src/api/tasks.py:335-338`（per-claim evidence）、`:362-370`（4 角色各 2 查询：最新 ReviewAction + users name）；同型：`src/api/review.py:194-196`、`src/api/tasks.py:1444-1446`。
- 修法：evidence 一次 `IN` 查询分桶；ReviewAction 用 `DISTINCT ON (review_session_id)` 或子查询；users 一次 `IN`（review.py:154-159 已有正确示范）。
- 收益：详情页 SQL 20-40→~10；风险低；工作量 **S**。

### P1-6 p95 指标全表扫 + Python 排序
