## 2. 架构速览（调试必备）

```
浏览器(Vue3 SPA, static/ 无构建)
   │ HTTP+SSE :8005
FastAPI 后端 (uvicorn 单进程 asyncio)
   ├─ 调度器 src/stream/scheduler.py（优先级队列+自适应并发）
   ├─ 双路径流水线 src/pipeline/orchestrator.py
   │   staged 变体(默认): task_import→ref_seed→text_check→ref_collect
   │     →agent_evidence→agent_draft→agent_pages→agent_assets
   │     →rule_check→cross_check→risk_classify→review_queue
   │     →batch_signoff→publish_snapshot
   │   agent_assets 内 IMAGE_COMPOSE_MODE(默认开)=程序文字+AI无文字画面混合合成
   │     （PIL+微软雅黑渲染文字，compose v6 版式/宫格；失败回退模型直出）
   │   （AGENT_PIPELINE_ENABLED=false 可切 13 节点直连兜底；monolith deprecated）
   ├─ 创作网关客户端 src/gateway/dsh_client.py
   │   → HTTP :8901 dsh_serve（薄层，内嵌 dsh harness 子进程）
   │   → LLM（deepseek 主/kimi 备）+ MCP 工具（qvp_mcp stdio 子进程）
   └─ PostgreSQL 16（asyncpg）＋ OpenSERP（搜实景图）
```

三道人工关卡：`awaiting_text`（文字核查）→ `awaiting_refs`（参考图确认）→ `review`（审图）。
MCP 工具四个创作能力：web_search / image_search / generate_images / ocr_image，走 `qvp_mcp/`。

## 3. 本机搭建（Windows + Docker Desktop）

前置：Docker Desktop、Git Bash、Python 3.12（可选，容器内已带）。

```bash
# 1) 克隆分支
git clone -b release/v0.1.2 git@github.com:zhangleifire-coder/qvp3.git
cd qvp3/code

# 2) 准备依赖容器（PG + OpenSERP，若本机已有可复用）
docker run -d --name qvp-postgres -p 5433:5432 -e POSTGRES_USER=qvp -e POSTGRES_PASSWORD=qvp -e POSTGRES_DB=qvp postgres:16
docker run -d --name qvp-openserp-local -p 7001:7000 karust/openserp:latest serve -a 0.0.0.0 -p 7000

# 3) 填密钥：把交接文件 §1 全部写入 code/.env（.gitignore 已排除，勿入库）

# 4) 构建镜像并启动（注意环境变量必须显式传入）
docker build -f deploy/Dockerfile.dsh -t qvp3-app:latest .
MSYS_NO_PATHCONV=1 docker run -d --name qvp3-app --network bridge -p 8005:8005 \
  -v "$PWD/.env:/app/.env:ro" \
  -v qvp3_qvp3_generated:/app/static/generated -v qvp3_qvp3_exports:/app/exports -v qvp3_qvp3_dshhome:/data/dsh \
  -e DATABASE_URL=postgresql+asyncpg://qvp:qvp@host.docker.internal:5433/qvp \
  -e OPENSERP_BASE_URL=http://host.docker.internal:7001 \
  -e DSH_SERVE_BASE_URL=http://127.0.0.1:8901/v1 \
  -e MCP_ENABLED=true -e MCP_COMMAND=/usr/local/bin/python \
  -e MCP_ARGS='["-m", "qvp_mcp"]' -e MCP_PYTHONPATH=/app \
  -e MCP_TOOL_TIMEOUT_MS=1800000 \
  -e MCP_EXTRA_ENV='{"LITELLM_LOCAL_MODEL_COST_MAP": "true", "PYTHONUTF8": "1"}' \
  -e DSH_WORKSPACE=/app -e LITELLM_LOCAL_MODEL_COST_MAP=true \
  --restart unless-stopped qvp3-app:latest

curl http://127.0.0.1:8005/healthz   # {"status":"ok"} 即成功
```

打开 `http://127.0.0.1:8005`，admin 登录（密码见交接文件）。

**省钱调试**：`.env` 设 `MOCK_IMAGE_GEN=true` 即占位图模式（不调生图 API）；文本调用仍真实计费。
**开关速查**：`AGENT_PIPELINE_VARIANT=staged/monolith`；`TEXT_CHECK_USE_REFS`（文案是否看图起草）。

**网络受限时的备选**（同事机器拉不动 Docker Hub / npm 时）：
- 基础镜像离线包：交接人执行 `docker save python:3.12-slim node:24-slim postgres:16 karust/openserp:latest -o /tmp/qvp3-base.tar` 发给同事，`docker load -i qvp3-base.tar` 后再 build。
- npm 走国内镜像：构建加 `--build-arg NPM_REGISTRY=https://registry.npmmirror.com`。
- pip 已在 Dockerfile 内置清华源；playwright 二进制内置 npmmirror 源。

## 5. 常见坑（都踩过）

1. **MCP 工具没挂载**（症状：生图节点 `FileNotFoundError`、transcripts 无工具调用）→ 检查容器 env 是否传了 `MCP_COMMAND/MCP_ARGS/MCP_PYTHONPATH/MCP_ENABLED`；dsh_serve 启动时生成 patch：`docker exec qvp3-app grep -c mcp-qvp /data/dsh/dsh-serve.mcp.patch.yml` 应为 1。
2. **Git Bash 路径转换**：`-e XXX=/app` 会被转成 `C:/Program Files/Git/...` → 命令前加 `MSYS_NO_PATHCONV=1`；`docker exec` 里的 `/tmp` 路径同理。
3. **shell 脚本 CRLF**：用 Python/编辑器改 `.sh` 后必须保持 LF，否则容器 `exec format error`。`file xxx.sh` 确认无 CRLF。
4. **改了代码必须重建镜像**：`docker build -f deploy/Dockerfile.dsh -t qvp3-app:latest .`（ENTRYPOINT 不进镜像的环境变量除外）。
5. **测试基准**：`docker exec qvp3-app python -m pytest tests/unit/ -q`（约 9 分钟）。已知 11 个预存失败（模型改名 v4→flash、费率字段演进等，与功能无关），新增失败才是问题。
